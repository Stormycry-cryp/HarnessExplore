# 初始诊断与定级

## 使用方式

逐题提问。每题要求 150-300 字左右；学习者可以说“不知道”。不要在五题完成前教学或透露评分点。

## 五道开放简答题

1. 用户让 Coding Agent 修复一个报错。请从用户输入开始，解释模型、Harness、工具和结果回填之间发生了什么；工具失败时系统该怎么处理？
2. 请区分 permission、sandbox、approval。以“Agent 想执行一个需要联网且会写工作区外文件的命令”为例说明三者如何配合。
3. 请区分 context window、context engineering、KV cache、long-term memory、task state 和 `AGENTS.md`。它们分别解决什么问题？
4. 一个复杂代码任务要拆给两个 subagent。你会如何分工、传上下文、通信、避免写冲突，并在失败后动态重规划？
5. 你会如何判断一个 Agent 产品真的有效？请给出最小 trace、badcase 和 eval 方案，并说明任务完成率之外还要看什么。

## 评分维度

每题 0-4 分，总分 20：

- `0`：空白或核心方向错误。
- `1`：能说出名词，但混淆边界。
- `2`：机制大体正确，缺少关键链路或失败处理。
- `3`：机制、边界和主要取舍正确，能联系工程产物。
- `4`：可向工程师清晰说明，能指出风险、可观测性和产品决策依据。

不要只按关键词计分。答案正确但靠猜，最多 2 分。

## 理解等级

- `0-4`：L0 初识。先建立术语与机制地图。
- `5-8`：L1 基础。能识别概念，边界不稳定。
- `9-12`：L2 工作理解。能跟进方案，需要工程师补全细节。
- `13-16`：L3 产品应用。能写要求、看 trace、讨论取舍。
- `17-18`：L4 工程沟通。能主持方案评审并识别薄弱假设。
- `19-20`：L5 Harness Owner。能系统拆解、评估和推动模型/Harness 协同迭代。

输出总分、分题分数、证据、最危险误区和课程优先级。不要为了鼓励抬分。
